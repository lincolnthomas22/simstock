# The SimStock match server

The referee for 1v1 matches. It is not a relay: it holds the clock, the money
and the price path, and a client is only ever told what has already happened.

It shares `sim.js` with the browser, so the market both players trade is
generated by the same code on both sides, and any finished match can be
replayed from the seed it hands back at the bell.

## Running it

```sh
cd server
npm install
npm start          # listens on 8080, or $PORT
npm test           # 23 protocol tests against a real server
```

Then in the game's Versus room, put `ws://localhost:8080` in the match server
box and press Connect.

### Settings

| Variable | Default | What it does |
| --- | --- | --- |
| `PORT` | `8080` | Port to listen on. `0` picks a free one, which is how the tests run. |
| `ALLOWED_ORIGINS` | *(unset)* | Comma-separated list of origins allowed to connect. Unset accepts anyone, which is what you want while testing. Set it to your own site before you point real players at it. |

`GET /health` returns room and match counts, which is what the deploy health
check watches.

## Deploying

The `Dockerfile` and `fly.toml` are in the repository root, not here, because
the image needs `sim.js` from the root as well as this directory. Build from
the root:

```sh
docker build -t simstock-server .
docker run -p 8080:8080 simstock-server
```

On Fly.io:

```sh
fly launch --no-deploy     # once, to claim the app name
fly deploy                 # from the repository root
```

An idle machine suspends and a connection wakes it, so a server nobody is
using costs nothing. The first player to connect after a quiet spell waits a
second or two for the wake-up. A machine with a match running has open
sockets, so it is never stopped mid-match.

Railway and Render work the same way from the same Dockerfile. Whatever you
use, the address players need is the `wss://` one — a page served over https
cannot open a plain `ws://` socket.

## How a match runs

```
  A                         server                        B
  |-- host {password,       |                              |
  |         risk, ticks} -->|  room opens, waiting         |
  |<-- hosted ------------- |                              |
  |                         |<---------- join {password} --|
  |                         |  generates the whole path    |
  |                         |  from a fresh seed           |
  |<-- start {stock, ------ | ------- start {stock, ... }->|   only the opening price
  |          price}         |                              |
  |<-- tick {prices, news,  | -------------- tick {...} -->|   once a second
  |          you, them} ----|                              |
  |--- order {side, qty} -->|  filled at the server's tick |
  |<-- filled {cash, ------ |                              |
  |            shares}      |                              |
  |<-- over {outcome, ----- | -------------- over {...} -->|   + the full path and seed
  |          seed, prices}  |                              |
```

The important line is the third one from the bottom. Prices are revealed one
tick at a time, so neither player has the end of the match sitting in their
own browser. The full path only goes out once the result is settled, so a
match can be checked or replayed afterwards.

Orders are filled at whatever tick the *server's* clock is on. A client that
thinks it is somewhere else does not get to trade on that, and cash and
shares only ever change because the server said so.

## What it does not do yet

- **No reconnection.** A dropped socket forfeits the match. Rejoining a match
  in progress would mean keying players by a token rather than a connection.
- **No accounts, no ranking, no history.** Rooms live in memory and a finished
  match is forgotten.
- **No matchmaking queue.** You need a password from someone; there is no
  "find me anyone".
- **Two players per room.** Nothing in the protocol assumes that, but the room
  code does.
